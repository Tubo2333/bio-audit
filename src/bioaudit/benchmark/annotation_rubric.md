# 真值标注 rubric（annotation.v1）

> **角色分离（E6）**：标注者只读本 rubric 与任务文件。**不要读取任何规则文件、
> 规则清单、评分文档或引擎源码**——你的标注基于方法学常识与任务上下文，与规则
> 库内容无关。标注对象：任务轨迹中每条决策的"该 Agent 的这一步选择是否合理"。

## 标注对象

每个任务文件含若干决策：`step_id` / `decision_type`（工序名）/ `choice`（所选
方法）/ `rationale`（Agent 的理由）/ `context`（数据与背景）。

## 标签定义（三分类）

对每条决策，从以下三选一：

- **correct（正确）**：在给定 context 下，该选择符合该工序的主流标准做法，
  不会导致结论失真。例：多患者 scRNA 差异表达用 pseudobulk 聚合后检验；
  批量 RNA-seq 用 DESeq2/edgeR/limma-voom；多重检验用 FDR 校正。
- **error（错误）**：在给定 context 下，该选择方法学上不当，会导致结论失真或
  明显偏差。典型信号：
  * 跳过必要工序（如不做质控/双细胞去除/批次处理/多重检验校正，且数据明确需要）；
  * 方法与数据形态不匹配（如把原始 counts 当表达量直接比较、细胞级检验用于
    多患者组间比较、t 检验用于零膨胀的非正态数据）；
  * 无视已知的批次/重复结构；
  * 声称"独立/显著"但方法不支持（如仅单变量模型宣称独立预后）。
- **edge（边界）**：可辩护但非最优，或依赖场景判断——既不干净地正确，也不
  干净地错误。典型信号：方法可用但更优替代存在；参数选择随意但可接受；
  数据量偏小但方法本身成立。

## 判定要点

1. **以 context 为准**：同样的方法在不同 context 下可能不同标签（如
   `wilcoxon_rank_sum`：单样本探索（correct 的边缘）vs 多患者组间比较（error））。
2. **只评这一步**：不要因为轨迹其它步骤错误而牵连本步；每步独立。
3. **错误 vs 边界**：会导致结论失真的算 error；只是"不够优雅/可争议"的算 edge。
   拿不准时选 edge（标注器可写 confidence 与 note）。
4. **不查文献**：用方法学常识判断；不搜索、不查 PMID。
5. **输出格式**：JSONL，每行一条：
   `{"task_id": "...", "step_id": "...", "label": "correct|error|edge", "confidence": 0.0-1.0, "note": "一句话理由（可选）"}`
   每个任务的每条决策必须输出一行（无遗漏）。

## 难度评估（供预注册分层，不参与 gold）

标注完成后，对每个任务给出你对任务复杂度的直觉评分 1/2/3（1=简单，2=中等，
3=困难；依据：决策数量、错误隐蔽程度、类型跨度）。这不会替代正式难度标签
（正式标签由特征 rubric 计算），只作对照参考。
